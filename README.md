# jev-ai-gramax-classifier

MCP-сервер для работы AI-агентов (Claude Code, Z Code и других) с персональной вики на [Gramax](https://gram.ax). Классификатором работает [Jev](https://www.jevai.org).

## Цель

Экономить контекст и токены дорогих моделей. Классификацию, фильтрацию и отсев шума делает дешёвый Jev. Агенту достаются только нужные фрагменты, а тексты пишет он сам.

## Архитектура

- **Стек.** Python + uv, MCP по stdio. Сервер `gramax`, пакет `jev_gramax`, команда `jev-gramax-mcp`.
- **Генеративного LLM в сервере нет.** Сервер детерминированный плюс Jev (TypeSafe `POST /v1/systemone`, вопросы типа `choice` и yes/no).
- **Файлы.** Сервер работает напрямую с файлами каталога Gramax из `GRAMAX_CATALOG`. Каталог один, но код готов к списку.
- **Git.** Сервер только читает `git status` (для удаления) и ничего не коммитит. Изменения публикуются через Gramax.
- **Отправка в Jev.** NDA-данных в вики нет, поэтому в Jev можно отправлять полный текст, с лимитом ~1500 символов на кандидата.

## Модель Gramax

- **Категории** — папки, у которых `_index.md` без тела. Папки с телом в `_index.md` — составные документы (курсы): Jev их не предлагает, но агент может указать их явно.
- **Статья.** Frontmatter: `order`, `title`, `properties`. Новая статья получает `order` = максимальный в папке + 1. Slug — транслит заголовка в нижнем регистре, до 50 символов, при коллизии суффикс `-2`. Тело — обычный Markdown от агента.
- **Свойство «Тип».** Enum со значениями `Course`, `YouTube Video`, `Article`, `How-to`, `Tool`, `Rules`, `Note`. Заводится в Gramax, сервер схему только читает.
- **Inbox.** Папка `inbox/` в корне каталога. Заметка попадает туда, только когда Jev отвечает, что не подходит ни один раздел.

## Tools

### Чтение

| Tool | Что делает |
| --- | --- |
| `wiki_tree(path?, depth?)` | Компактное дерево: заголовки, пути, число статей |
| `wiki_search(query, section?, property?, limit?)` | Возвращает фрагменты `path#heading` со сниппетами |
| `wiki_read(path, heading?, raw?, include_diagrams?)` | Очищенный Markdown статьи или одного раздела плюс `etag` |

**Как устроен поиск:**
- индекс гибридный: BM25 со стеммингом ru/en плюс мультиязычные эмбеддинги (`paraphrase-multilingual-MiniLM-L12-v2` через fastembed, ~220 МБ; `multilingual-e5-small` в fastembed нет), объединение через RRF;
- единица индекса — фрагмент статьи по заголовку H2/H3;
- кэш лежит в `~/.cache/jev-gramax` и пересчитывается по mtime изменённых файлов;
- затем Jev делает rerank: top-10 фрагментов, по одному вопросу yes/no на фрагмент в одном запросе, порог 0.5;
- если Jev недоступен, возвращается top-k по score; без модели эмбеддингов работает только BM25.

**Очистка разметки при чтении:**

| Разметка Gramax | Что получает агент |
| --- | --- |
| `<note>` | цитата `>` с меткой типа |
| `<table>` | Markdown-таблица, если нет объединённых ячеек |
| `<video>` | ссылка |
| `<mermaid>` | заглушка; код только с флагом `include_diagrams` |
| картинки | ссылка с абсолютным путём |
| `<view>`, `<br/>` | удаляются или превращаются в перенос строки |
| PDF | только ссылка |

### Запись (фаза 3, только по явной просьбе пользователя)

- `wiki_save(title, body, section?, properties?, force_new?)` — **один запрос к Jev** с тремя вопросами:
  - раздел: категории + `none`;
  - тип;
  - дубль: `new` + top-5 кандидатов из поиска.

  Логика по результату:
  - дубль ≥ 0.7 → не писать, вернуть кандидата;
  - раздел ≥ 0.6 → записать;
  - раздел < 0.6 или Jev недоступен → вернуть top-3, не писать;
  - `none` → записать в `inbox/`.
- `wiki_edit(path, old, new, etag)` — замена строки в сыром файле.
- `wiki_update_meta(path, title?, properties?, etag)`.
- `wiki_delete(path)` — только файлы, которые есть в git и не изменены. Разделы удаляются только пустые, вложения не трогаются.
- `wiki_create_section(parent, title)` — только по явной просьбе пользователя.
- Все записи атомарные (временный файл + rename).

## Поведение агентов

Через поле `instructions` MCP-сервера: читать можно самостоятельно, писать, править и удалять — только по явной просьбе пользователя. Описания tools на английском и короткие.

## Фазы

1. **Чтение.** Парсер Gramax, очистка разметки, гибридный индекс, `wiki_tree`, `wiki_search`, `wiki_read`, rerank через Jev с fallback.
2. **Оценка.** `scripts/eval.py`: leave-one-out для раздела и типа, около 20 запросов для поиска и rerank, замер экономии токенов. Подбор порогов на закреплённой версии `JEV_MODEL`.
3. **Запись.** `wiki_save`, `wiki_edit`, `wiki_update_meta`, `wiki_delete`, `wiki_create_section`.

## Не входит в MVP

Вложения при записи, индексация PDF, перемещение и переименование статей, блок обслуживания (массовая разметка, поиск дублей по всей вики, разбор Inbox), несколько каталогов, создание разделов по инициативе агента.

## Установка

### Claude Code

```bash
claude mcp add gramax -e JEV_API_KEY=... -e GRAMAX_CATALOG=/path/to/catalog -- \
  uvx --from git+https://github.com/sergeiboikov/jev-ai-gramax-classifier jev-gramax-mcp
```

### Из локального клона

```json
"gramax": {
  "command": "uv",
  "args": ["run", "--directory", "/path/to/jev-ai-gramax-classifier", "jev-gramax-mcp"],
  "env": { "JEV_API_KEY": "...", "GRAMAX_CATALOG": "/path/to/catalog" }
}
```

При первом поиске скачивается модель эмбеддингов (несколько сотен МБ) в кэш fastembed.

## Настройки

| Переменная | Обязательна | По умолчанию |
| --- | --- | --- |
| `GRAMAX_CATALOG` | да | нет; путь к каталогу Gramax (папка с `.doc-root.yaml`) |
| `JEV_API_KEY` | нет | нет; без ключа поиск работает без rerank. Нужен ключ TypeSafe с [console.typesafe.ai/keys](https://console.typesafe.ai/keys) |
| `JEV_MODEL` | нет | `jev-latest` |
| `JEV_RERANK_THRESHOLD` | нет | `0.5` |
| `JEV_TEXT_LIMIT` | нет | `1500`; символов на кандидата в запросе к Jev |
| `GRAMAX_EMBED_MODEL` | нет | `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`; `none` отключает эмбеддинги |
| `GRAMAX_CACHE_DIR` | нет | `~/.cache/jev-gramax` |

## Разработка

```bash
uv sync
uv run pytest                 # офлайн-тесты, без ключа и без сети
uv run jev-gramax-mcp         # сервер на stdio
```

## Что нужно проверить

- Сохраняет ли Gramax ключ `description` в `_index.md`. Если нет, переопределения описаний разделов будут лежать в `.jev.yaml`.
- Подхватывает ли открытый Gramax файлы, созданные снаружи.
- Нормально ли Gramax отображает обычный Markdown, который пишет агент.
- Реальные лимиты Jev: длину `state` и число вопросов в одном запросе.
